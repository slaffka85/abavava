# chat-abavava — roadmap

## v1.0 (текущее состояние)

Аккаунты и сессии, личные и групповые чаты, сообщения в реальном времени, присутствие,
индикатор набора, отметки прочтения, аудио/видео звонки 1:1, история звонков,
docker-compose, автотесты и документация. Подробности — в [PROJECT-PLAN.md](PROJECT-PLAN.md).

## v1.1 — надёжность звонков и покрытие медиа

**Цель:** звонок должен соединяться в любой сети, и это должно быть проверяемо
автоматически.

| Задача | Зачем | Оценка |
|---|---|---|
| TURN (coturn) в compose, временные креденшелы через `GET /config/ice` | сейчас звонки не проходят через симметричный NAT и мобильные сети | 1–2 дня |
| ✅ E2E-проверка медиа в браузере (`web/tools/media-check.mjs`) | сделано: 33 проверки, двустороннее видео и звук, скриншоты и JSON-отчёт | — |
| Запуск `media:check` в CI на агентах с браузером | проверка медиа должна ловить регрессии автоматически, а не по желанию | 0.5 дня |
| Метрики Prometheus (`/metrics`): соединения, доставки, длительность звонков, ошибки | без метрик невозможно эксплуатировать | 1 день |
| Redis Pub/Sub для рассылки за `domain.Broadcaster` | несколько инстансов API без sticky sessions | 2–3 дня |
| Ice-restart по кнопке и индикатор «плохое соединение» в UI | пользователь понимает, что происходит | 1 день |

**Критерий:** звонок между двумя браузерами в CI даёт ненулевой медиатрафик (достигнуто
локально); в `docker-compose` добавлен TURN; метрики и дашборд собираются.

## v1.2 — продуктовая зрелость чата

| Задача | Зачем | Оценка |
|---|---|---|
| Вложения (изображения, файлы): объектное хранилище, presigned URL, лимиты | без файлов мессенджер не используют в работе | 4–5 дней |
| Редактирование и удаление сообщений (soft delete, `edited_at`) | поля в схеме уже есть | 2 дня |
| Поиск по истории (`pg_trgm`/полнотекстовый поиск) | базовая потребность в переписке | 3 дня |
| Push-уведомления (Web Push) для офлайн-пользователей | сейчас офлайн-пользователь не узнает о звонке | 3 дня |
| Загрузка аватаров, превью ссылок | качество интерфейса | 2 дня |
| Партиционирование `messages` по `created_at` | рост таблицы на порядках | 2 дня |

## v2.0 — групповая коммуникация

| Задача | Зачем | Оценка |
|---|---|---|
| Групповые звонки через SFU (LiveKit или Pion SFU) | главный запрос после 1:1 | 2–3 недели |
| Демонстрация экрана и запись | рабочие сценарии | 1 неделя |
| Расширенная модель групп: каналы, права, упоминания, приглашения по ссылке | переход от «чата для двоих» к командному продукту | 2 недели |
| E2E-шифрование (MLS или Signal-протокол) | требования безопасности | 4–6 недель |
| Мобильные клиенты (React Native) или PWA с push и фоном | доступ с телефона | 3–4 недели |
| Модерация и админка, аудит действий | эксплуатация в организации | 2 недели |

## Технический долг, который стоит закрыть раньше v2

| Долг | Риск | Оценка |
|---|---|---|
| ✅ Медиа покрыто проверкой в браузере | закрыто: `npm run media:check` (33 проверки, двустороннее видео и звук) | — |
| Хаб в памяти процесса | нельзя масштабировать API горизонтально (см. v1.1) | входит в v1.1 |
| Нет ограничения на число сообщений в группе/диалоге в единицу времени | злоупотребление рассылкой | 1 день |
| Нет резервного копирования и стратегии восстановления БД | потеря данных | 1 день |
| `ILIKE '%...%'` в поиске пользователей | не масштабируется на большую базу | входит в v1.2 (поиск) |
| Отсутствует проверка версии WS-протокола на сервере | старый клиент не получит понятной ошибки | 0.5 дня |
